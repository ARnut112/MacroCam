# MacroCam — ผลทดสอบ

ข้อมูล ณ 15 ตุลาคม 2026 ใช้ข้อมูลสมมติทั้งหมด ไม่มีการโอนเงินหรือสร้างยอดขายจริง

## ผลตรวจที่มีหลักฐาน

| --------------------------------------- | ------------------------------------------------------------------------------- |
| TypeScript (`npm run typecheck`)        | ผ่าน และ production build ตรวจ TypeScript ผ่านอีกรอบ                            |
| Unit tests (`npm test`)                 | ผ่าน 19 กรณี: backend 7 และ catalog 12 ไม่มีกรณีล้มเหลวหรือข้าม                 |

## ขอบเขต unit tests

ตัวกรองตรวจชื่อ ยี่ห้อ รุ่น คำไทย เมาท์ ช่องว่าง ตัวพิมพ์ หมวด สภาพ สต็อก ตัวกรองร่วม สินค้าซ่อน/หมด ผลว่าง เรียงวันที่/ราคา/ชื่อ และไม่แก้รายการต้นฉบับ

Backend ตรวจการไม่ใช้ราคาที่ลูกค้าส่ง เบอร์โทร ข้อมูลและจำนวนผิดรูปแบบ ลำดับสถานะ สิทธิ์ผู้กระทำ การเก็บไฟล์เมื่อข้อผิดพลาดอาจซ่อน transaction ที่สำเร็จ ขนาด/MIME/signature ของรูป token และคอลัมน์/URL ที่ไม่อนุญาต ชุดนี้ไม่ติดต่อ Supabase จริง

## ผลตรวจเบราว์เซอร์

ใช้ Codex In-app Browser บน Windows เริ่มด้วย `npm run dev` แล้วตรวจรุ่น production ในเครื่องด้วย `npm run build` และ `npm start`

ตรวจเดสก์ท็อปและโหมดมือถือ/แท็บเล็ตด้วย viewport capability ความกว้างเนื้อหาที่วัดจาก DOM ในโหมดมือถือ 416 CSS px และแท็บเล็ต 836 CSS px หน้าแรก รายการสินค้า รายละเอียด และหลังร้านที่วัดมี scrollWidth เท่ากับ clientWidth ไม่ล้นแนวนอนในหน้าที่ตรวจ ไม่ใช่การทดสอบโทรศัพท์จริงทุกยี่ห้อ

- ผ่าน: หน้าแรก รายการและรายละเอียดแสดงผล สลับรูป Canon R6 II เป็นด้านหลังได้
- ผ่าน: ค้น fujifilm พบ 2 รายการ กรองเลนส์เหลือ 1 ค้นไม่พบมีข้อความและทางกลับ
- ผ่าน: เปิดตัวกรองมือถือ เลือกเลนส์ ปิดแผงและแสดง 4 รายการ เมนูมือถือเปิด/ปิดได้
- ผ่าน: เรียงราคาต่ำไปสูงและเปิด URL ตัวกรองซ้ำแล้วคงผลเดิม ใช้ native history อัปเดต URL ทันที
- ผ่าน: เพิ่ม Sony A7 IV 1 ชิ้นได้ เพิ่มเกินสต็อกถูกปฏิเสธ สินค้าหมดเบลอและปิดปุ่มเพิ่ม/บันทึกใหม่
- ผ่าน: รายการบันทึกคงอยู่หลังรีเฟรช เพิ่มจากรายละเอียดและนำออกจากตะกร้าได้ ตะกร้าว่างมีทางกลับ
- ผ่าน: Fujifilm X-T5 เพิ่มเป็น 2 ชิ้น ยอด 111,800 บาท ลดเหลือ 1 ยอด 55,900 บาท แล้วนำออกได้
- ผ่าน: กรอกข้อมูลจัดส่งสมมติ สร้างเลข DEMO เปิดหน้าชำระเงินทันที รีเฟรชยังเป็นเลขเดิม
- ผ่าน: หน้าชำระเงินจำลองไม่มี QR รับเงินจริง มีข้อความไม่ต้องโอนและเส้นตาย 1 ชั่วโมง
- ผ่าน: ติดตามด้วยเบอร์ผิดไม่แสดงรายละเอียด เปลี่ยนเป็นเบอร์ที่ตรงกันแล้วเปิดรายการเดิมได้
- ผ่าน: หลังร้านตัวอย่างอ่านอย่างเดียว ไม่มีบัญชีจำลอง API ไม่เปิดข้อมูลเมื่อไม่มีการตั้งค่าและสิทธิ์
- **ยังยืนยันไม่ได้:** การเลือก/ส่งไฟล์ผ่านเบราว์เซอร์ถูกปฏิเสธสิทธิ์อัปโหลด จึงไม่ทดสอบต่อหรือใช้วิธีเลี่ยง ขนาด MIME และ signature ตรวจผ่าน unit tests เท่านั้น
- **ยังตรวจไม่ครบ:** หลังร้านที่เข้าสู่ระบบจริง keyboard navigation ทั้งเส้นทาง storage ถูกบล็อก สินค้าไม่มีรูป และหลายเบราว์เซอร์บนอุปกรณ์จริง

พบ hydration mismatch ระหว่างแก้ด้วย hot reload จึงตรวจรอบสุดท้ายบน production build ที่เริ่มใหม่เพื่อไม่ใช้ไฟล์เก่าปะปน ไม่ถือผลระหว่าง hot reload เป็นผลรุ่น production

## ต้องตรวจกับ Supabase ก่อนเปิดขาย

ใช้ Supabase โปรเจกต์ทดสอบใหม่ที่ว่างตาม [คู่มือฐานข้อมูล](../supabase/README.md) ห้ามใช้ Bakkabook หรือฐานข้อมูลที่มีคำสั่งซื้อจริง

1. รัน migration และ supabase/tests/invariants.sql ซ้ำบน Supabase จริง แม้ผ่าน PGlite แล้ว เพราะ auth/storage ในเครื่องเป็นแบบจำลอง
2. ตรวจบัญชี allowlist และบัญชีทั่วไป ผู้ไม่มีสิทธิ์ต้องอ่าน/แก้คำสั่งซื้อ เรียก RPC หรืออัปโหลดไฟล์ผู้ดูแลไม่ได้
3. ตรวจ checkout เมื่อ flag ปิด คีย์/secret ไม่ครบ หรือ QR/บัญชี/นโยบายขาด ต้องไม่รับคำสั่งซื้อ
4. เปิด 2 session สั่งชิ้นสุดท้ายพร้อมกัน สำเร็จเพียงหนึ่ง อีกคำขอได้ STOCK_UNAVAILABLE สต็อกไม่ติดลบ
5. ส่ง key เดียวกันพร้อมกัน ต้องได้ UUID เดียวและจองครั้งเดียว ใช้ key เดิมกับข้อมูล/ผู้สั่งต่างกันต้องถูกปฏิเสธ
6. เปิดหน้าแก้สินค้าเก่าค้าง แล้วจองจากอีก session การบันทึกเก่าต้องได้ 409 ไม่คืนสต็อกที่จองไปแล้ว
7. ตรวจ JPG/PNG/WebP สูงสุด 4 MiB (หน้าเว็บเรียก 4 MB) และไฟล์ปลอม สลิปต้องไม่มี URL สาธารณะ ลิงก์ผู้ดูแลชั่วคราวหมดอายุได้จริง
8. ส่งสลิปทันกำหนดเป็นรอตรวจ ร้านยืนยันก่อนชำระแล้ว กรอกขนส่ง/พัสดุก่อนส่ง ลูกค้ายืนยันรับหลังส่งเท่านั้น
9. ยกเลิก/หมดอายุซ้ำคืนสต็อกครั้งเดียว ไม่ยกเลิกรายการส่งแล้ว สลิปทันเวลาไม่หมดอายุด้วยกฎ 1 ชั่วโมง
10. ตั้งงานทุก 1 นาทีด้วย secret รายการไม่ส่งสลิปหมดอายุครบ 60 นาที คืนสต็อกรอบถัดไปแม้ไม่มีคนเปิดเว็บ secret ผิดถูกปฏิเสธ
11. ตรวจ rate limit หลาย instance และ origin ตรงโดเมน ข้อผิดพลาดไม่เปิดข้อมูลลูกค้าหรือคีย์
